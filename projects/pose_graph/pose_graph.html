Pose Graph Optimization

A pose-graph optimization pipeline for 2.5D SLAM (Simultaneous Localization and Mapping), built from scratch in C++.

VivianMak/pose_graph_optimization_for_SLAM

01 / Gathering Simulation Data

To develop and test the algorithm, we needed odometry and LiDAR data. We generated it using the TurtleBot 4 simulator and ROS2, recording a ROSbag and writing a ROS2 node that saved the scan and odometry messages to a binary file we could read from directly.

The simulated odometry and LiDAR are effectively perfect, so we injected artificial drift — small, accumulating, normally distributed offsets added to x and y at each measurement — to give the optimizer realistic error to correct.

02 / Constructing the Pose Graph

Before optimization can begin, the raw odometry has to be converted into the underlying graph structure the solver operates on: a sequence of nodes with relative transformations between them stored as edges. This chain of constraints forms the "backbone" of the graph, encoding how the robot moved from one timestep to the next; loop-closure constraints from ICP are later added directly onto it.

The structure is built from a few core data structures — Point, Pose, Edge, and Node. Each Node corresponds to one moment in time and stores the robot's estimated pose from odometry, while each Edge stores a 3×3 homogeneous transform encoding how one node's pose relates to another.

03 / Transformations with ICP

Pose graph optimization needs two independent estimates of where the robot is. Odometry gives one directly. For the second, we align overlapping LiDAR scans using ICP (Iterative Closest Point): given two scans of approximately the same environment, ICP outputs a transform mapping the source scan into the destination scan's frame, creating a constraint between the two corresponding nodes.

We implemented the point-to-plane variant: compute normals on the destination scan, seed the source scan with the odometry estimate, then repeatedly match each source point to its nearest destination neighbor, measure the error along that point's normal, and solve a least-squares system for the transform update — iterating until convergence.

04 / Gauss-Newton Global Optimization

With the graph and its constraints in place, we solve the nonlinear least-squares problem with the Gauss-Newton algorithm. It back-propagates the noisy relative pose measurements across the whole graph to recover a globally consistent set of "real" poses, treating each timestep's laser scan as a source of truth and iteratively minimizing the error of overlapped points until convergence.

Each iteration derives an error function for every adjacent pair of nodes, linearizes it with a first-order Taylor expansion around the current estimate, and computes the Jacobian of that error. These assemble into the global linear system HΔx = −b, which is solved for the pose update Δx and applied across all nodes, repeating until the trajectory converges.
